# Plane Work Continuity Platform 详细设计目录

本目录把 `ReadMe.md` 和主实施计划落成可独立维护、可并行实现、可独立测试、可统一集成发布的设计文档集合。

## 设计基线

- 需求基线：[ReadMe.md](../../ReadMe.md)
- 总实施计划：[主实施计划](../superpowers/plans/2026-10-20-plane-work-continuity-platform.md)
- 需求追踪：[requirements-matrix.yaml](../traceability/requirements-matrix.yaml)
- 记忆实现基线：[ai-memory 适配设计](vendor/ai-memory-adoption.md)
- 当前 ai-memory 参考版本：`v3.1.1`；实现前必须重新确认上游版本、提交哈希和兼容性。

## 文档分层

| 目录 | 内容 | 维护方式 |
|---|---|---|
| `00-baseline` | 需求、边界、领域模型、记忆、切换流程、安全和架构决策 | 架构组维护，变更必须有 ADR |
| `01-contracts` | WCP、事件、MCP、Schema、版本和错误契约 | 契约组维护，先契约后实现 |
| `02-subprojects/P0-P8` | 每个子方案的目标、边界、输入输出、任务、验收和依赖 | 对应子方案负责人维护 |
| `02-subprojects/tasks` | 每个子任务的独立详细设计 | 任务负责人维护，必须通过协接契约 |
| `03-integration` | 跨任务协接、集成环境、接口冻结和合并规则 | 架构与发布组共同维护 |
| `04-testing` | 测试分层、每模块独立校验、测试数据、故障、安全、性能和智能评测 | 测试组维护 |
| `05-release` | 发布、部署、迁移、备份、回滚、上线和运行手册 | 发布运维组维护 |
| `06-planning` | 整体开发波次、P0–P8 模块计划、37 个子任务、测试任务和真实形状数据校验计划 | 计划负责人维护，任务变更必须同步追踪矩阵 |
| `vendor` | 外部组件的版本、能力、限制、适配和升级策略 | 架构组维护 |

## 阅读顺序

1. `00-baseline/`：理解权威边界和不可违反的设计原则；
2. `01-contracts/`：理解所有并行团队共享的接口；
3. 对应 `02-subprojects/Px/README.md` 和 `tasks/T*.md`；
4. `03-integration/`：理解模块接口、任务协接和集成边；
5. `04-testing/`：先阅读对应 P0–P8 独立校验文档；
6. `06-planning/`：按整体计划、模块计划和统一测试数据计划执行；
7. `05-release/`：理解统一完成定义和上线门禁。

## 并行实现原则

- 任何实现只能依赖本文档定义的接口、事件和 Fixtures；
- 不得直接依赖其他任务的内部代码或数据库表；
- 每个任务必须有独立测试和可复现的验收命令；
- 接口变更必须同时更新契约、协接文档、追踪矩阵和测试；
- 未通过子方案验收的代码不能进入统一集成分支；
- 所有生产行为都必须能回到需求编号、设计章节、代码变更和测试证据。
