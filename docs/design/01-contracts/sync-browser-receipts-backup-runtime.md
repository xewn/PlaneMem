## 专用入口与历史含义

`/sync/receipt` 新增在另一标签页打开 `/sync/receipt/receipt-backup` 的入口，不替换当前已经固定的原查询。明确点击后才准备全部历史回执备份或读取文件；导入只核验并审阅，不自动恢复。范围为本浏览器同源 profile 内跨账号/项目的全部已保存历史回执，包括同一事件不同查询 trace、历史 accepted/conflict/not-observed 结果及完整原查询/事件。

审阅显示总份数、整份摘要及每份原身份、事件 ID/类型、原查询 trace、历史结果、回执文档摘要，每屏 20 份仅用于展示；下载与 JSON 复制始终包含完整备份。摘要顺序不表示时间顺序，历史结果不表示当前服务器状态。页面不将恢复的历史回执变为新的查询响应，也不把其中的原查询另存到原查询库。

明确勾选恢复全部记录后才可提交，每次尝试清除勾选。成功、已存在或未知失败后保留完整审阅文件直到关闭，提供下载和复制；准备下载不代表文件已落盘。空备份可以审阅/下载，无需写入。忙碌、同步点击锁、卸载取消和审阅焦点共用 `backup-review.tsx`；原查询页面也使用该组件，继续保留独立的格式校验、文件名、适配器和范围说明。

## 文件结构与双层摘要

`SyncReceiptsBackupFile` 严格为 `{document,document_sha256}`。文档严格为 `{schema_version:1,kind:'workctx.sync-receipts-backup',entries}`；每项是完整既有 `workctx.sync-event-receipt` v1 文件，包含其原文档和 `document_sha256`。不能用单条文件或原查询备份冒充集合，也不从摘要目录构造缺失正文。

条目按每份回执文档摘要严格递增且唯一，不接受重复或自动排序；不同摘要的同一事件可同时存在，不能按 event_id 去重。每份完整回执复用已有结构、原身份/事件、trace、来源和 recorded/not-observed 校验，沿用原规范字段及事件内部属性顺序。

最多 256 份，集合文档最多 32 MiB，完整文件最多 32 MiB + 8192 字节；单份文件保留既有 2 MiB + 8192 上限及其更细内部限制。整个集合同时受 JSON 100000 节点/深度 64 限制，单份有效不保证组合后有效。文件声明大小、实际字节数和严格 UTF-8 解码均核验，可处理开头 BOM。超限拒绝整笔，不输出截断备份。

共享解析器仅做结构校验。浏览器独立计算规范集合文档 UTF-8 的 SHA-256，并逐份独立计算规范回执文档 SHA-256，两层都必须相符。合法集合摘要不能代替逐回执摘要核验；调用恢复时重新解析审阅文件并重算两层摘要。摘要仅证明内容自洽，不提供服务器签名、可信保存时间、来源认证或新的投递确认。

## 单次快照导出

`readBrowserSyncReceiptBackup` 在一个覆盖 `receipts/directory` 的 readonly 事务中读取两个实际数量，要求一致且未超过 256。按摘要键游标遍历全部正文槽，逐对核验规范完整原文、实际键、目录元数据和累计字节，终点核对条数并解析完整集合。相等数量但不同键、非法摘要键、单边缺失、非法元数据、损坏或非规范正文均失败，不跳过坏行。

读取在事务完成之后才返回结构快照，`prepareBrowserReceiptsBackup` 随后逐份验证实际摘要，再计算集合摘要并生成完整规范文件。任何内部摘要不符均不交付备份，不会将结构核验结果提前展示为成功。摘要在事务外异步执行，期间不重新读库，因而备份对应原单次读取快照。缺库返回空集合并中止初始 upgrade，不永久创建空库。

## 全部预检后的原子补入

`restoreReceiptsBackup` 在打开存储前完成整个文件和所有内层摘要核验；随后存储助手再次结构解析，准备每份原摘要槽、规范原文与目录。空集合返回零条结果，不打开库。非空显式恢复可初始化既有 v1 结构；建库 upgrade 与数据恢复事务分离，后续失败可能留下空的 v1 存储，不宣称所有失败都没有存储变化。

一个 readwrite 事务先预检全部目标槽，存在的正文和目录须成对且完整有效，正文须与刚核验全部摘要的文件逐字相同。完全相同的已有槽接受并计数，不能仅凭摘要键或目录相同而接受；单边缺失、同摘要异文或损坏均整批拒绝。全部预检结束后只 add 缺失的正文和目录，每对写入后完整读回并比较，再进入下一项。

所有请求在同步回调中排队，不在活跃事务中等待摘要 Promise。错误尝试 abort，只有事务完成且期限/取消检查通过才返回 restored/already-present 和总数、补入数、已有数。超时或完成时序不明保留未知状态和文件，不能承诺未写入。不覆盖、删除、清理或修复已有记录；不同摘要的其他历史结果、原查询库和队列保持独立。并发标签页可在完成后继续更改存储，此结果不保证未来状态。

## 期限、限制与待补证据

共享 `backup-operation.ts` 从文件读取或备份准备开始统一约束 30 秒单调期限，覆盖逐回执摘要、集合摘要和存储；每次异步完成及恢复准备/事务回调检查期限，迟到摘要不能开始新恢复。数据库打开和数据事务分别沿用 10 秒期限。卸载取消等待并尝试中止事务，WebCrypto 本身可能继续完成但结果被丢弃；同步解析/结构化克隆不能硬实时抢占，外部超大坏值无法在读取前完整限制。
