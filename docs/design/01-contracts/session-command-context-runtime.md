## 缺口与只读入口

交接创建表单原先从目录或原会话详情取得已验证身份。目录损坏、分页查询失败或原记录不可读时，页面可能无法显示已有创建请求的恢复表单，即使用户仍有查看自身身份或查询原回执的权限。本增量新增 `GET /v1/sessions/command-context`，对应 `session.command-context`，读取当前可信调用者元数据，不读取目录、会话、检查点或交接记录，不生成键、创建业务对象或查询业务回执。

HTTP 必须通过签名令牌验证，强制客户端身份，不使用 continuity 兼容匿名分支。拒绝查询参数、非空请求体声明、Transfer-Encoding、写条件及条件缓存/范围头；处理器也拒绝业务输入和上下文继承的写条件。成功返回 private, no-store，不使用写入幂等缓存。直接受信任嵌入需明确 authenticated_client=true 和真实未过期 token_expires_at，不能靠缺省未来到期时间通过。

访问需要已验证且未过期身份，以及 context.read/session.write/handoff.claim 中至少一种能力，或现有 admin 角色。策略动作按已有能力选择：显式 context.read 优先，其次 session.write 或 admin，最后 handoff.claim；仍执行原本地/OPA 范围授权和强制入口审计，不新增能力名或权限豁免。提示按现有 admin/能力语义计算，写会话提示同时包含领取提示，但实际后续命令仍重新授权。

本接口不查询项目是否存在、删除或可读，也不披露项目业务记录。返回的项目来自当前已授权令牌范围，不证明原项目或交接仍可访问。普通入口审计可依赖数据库，因此“独立于目录”不等于在鉴权、策略或审计故障时仍可工作。该请求没有目标 session_id，入口审计不虚构会话关联。

## 响应契约

```text
{schema_version:1,trace_id,source_refs:[],
 data:{identity:{tenant_id,workspace_id,project_id,actor_id,client_id},
       expires_at,permissions:{read_sessions,write_sessions,claim_handoffs}}}
```

`SessionCommandContextEnvelope` 完整对象最多 16 KiB，身份复用原恢复身份解析器，核对范围和 trace、精确字段、空来源数组、规范 UTC 毫秒到期时间及权限布尔关系。来源为空表示此结果来自当前已验证请求上下文，不冒充数据库记录来源；输出不含令牌、凭据或业务笔记。可信 CLI/MCP 适配还对比原身份、原到期时间和原能力提示，避免错接另一调用者结果。权限提示不授权写入，当前身份也不能替换已保存请求里的原身份。

处理器在返回前检查有效期，无法表示的可信上下文为 SESSION_COMMAND_CONTEXT_INVALID/500。SDK/Web 在收到并解析后拒绝已过期的结果；页面打开期间提示不会自动延长令牌或保证以后操作仍获授权。

## SDK、CLI 与 MCP

SDK `getSessionCommandContext(options?)`，选项 `WcpSessionCommandContextOptions` 支持 timeout_ms/signal，默认本地 30 秒。固定 scope/trace，GET 无业务正文，不继承写条件；构造上下文可选 actor/client 作为预期身份条件，响应独立核对。Fetch bounded-json 成功/错误各 16 KiB，校验 200、trace、媒体类型、UTF-8 和长度；完整对象解析后检查截止时间与到期。Fetch 自身预算独立生效，自定义 transport 也受 SDK 等待预算约束，但超时/取消不保证撤销已派发鉴权或审计工作。有限错误说明保留原 trace，不自动重试或保存。

CLI `sessions identity` 只接受可选 `--timeout-ms`（1–2147483647 毫秒），不接受 JSON、输入/输出文件、写键、队列或重复选项。网络固定令牌、项目和一次 trace，经 SDK 输出完整封套；嵌入也复用 SDK，并在派发前后验证可信身份、到期和能力，与返回完整数据比对。两条路径均不读取目录、不扫描旧请求或保存文件。示例 `workctx sessions identity --timeout-ms 30000` 仅说明源码接口，未执行。

MCP 新增 `get_session_command_context({})`，仅向符合可信身份/有效期/权限条件的调用者展示，调用时再次检查，清理继承写条件。固定 GET 路径与原上下文快照，成功仅接受 200/原 trace 响应头；完整数据须匹配原身份、有效期和能力。返回完整封套的单项 JSON 文本，内层对象限 16 KiB。只读、非破坏、幂等注解不证明结果长期不变；不创建资源 URI、自动恢复、写键或客户端文件，没有新增独立准备名额、期限、发送容量或通用错误脱敏保证。

## 独立交接恢复页

新增 `/handoffs/recover`，不接收 URL 业务参数，只读当前可信元数据后显示原创建请求表单，以及领取/续接原请求加载面板。Web 身份响应的成功/错误正文各限 16 KiB，沿用 30 秒本地等待，严格响应头、完整契约及过期检查。没有目录、会话或检查点详情前置请求；队列成功和错误视图的查找面板、按 ID 准备页、交接详情成功和失败视图都提供同标签页恢复链接，避免新标签页无法访问原 sessionStorage 的问题。

`CreateForm` 新增 recoveryOnly 模式：不准备新草稿，不生成新请求键，不显示“准备下一份”操作，也不轮换/清除原保存槽位。沿用原身份/project 的 sessionStorage 键、32,768 字符恢复文本上限、原请求绑定及导入/导出格式；重载时恢复原请求并视为结果未知，取消旧确认，不能按当前目录补造成功。原 checkpoint/session/target/key 全部保留，跨账号/客户端/项目导入被拒绝。

打开页面只读取身份并尝试恢复本标签页保存内容，不自动查询回执、重试创建、领取或续接。导入后用户明确查询原回执；需要重试时仍须确认原请求并走已有保存/授权/事务/回执逻辑。只有当前读取权限而无写权限时，可保留和导出本地原请求、显式请求查询；Gateway 会独立拒绝无权查询回执的请求。not-observed 或目录/详情不可读均不证明原创建失败，也不允许换键。

身份读取失败或全部相关权限丢失时页面保留错误与重新加载入口，不清除浏览器原请求，不伪造身份或自动发送。必须恢复合适的原身份/权限才能继续；页面不是离线全权限恢复器。原详情/笔记审阅和创建页面继续存在，恢复页确认成功后仍需独立读取当前交接状态。

## 领取与续接独立恢复增补（2026-11-03）

领取和续接分别提供两种明确加载方式：输入原父会话 ID 与交接 ID，从当前可信身份绑定的精确 sessionStorage 槽读取；或粘贴已导出的原恢复文本。只读取指定槽，不扫描或罗列其他存储，不请求当前交接、会话、检查点、历史列表或原回执。槽不存在、读取失败、格式损坏、身份或目标不符时保留输入和存储；没有本地请求不证明业务操作失败。

两种原格式均限 32768 个 UTF-16 单元，沿用 schema_version=1、各自 operation 和严格字段校验。领取键必须为 claim-{handoffId}-v{version}，续接键必须为 workbench-resume-{handoffId} 且 requireClaimed=true；不将任意 SDK/CLI 原请求自动转换为工作台格式。导入须匹配当前可信 tenant/workspace/project/actor/client。原父会话、交接、检查点、版本与键全部来自通过校验的原文本，不能凭输入 ID 或当前状态补造。

加载后固定一个原请求，并展示父会话、交接、检查点和请求键，复用 ClaimForm/ResumeForm 的 recoveryRequest 模式。初始结果为未知且确认未勾选；模式不允许从 idle 生成新请求，也不允许导入不同版本/参数替换当前原请求。当前详情没有被读取，页面不会以 eligible=false 声称该交接当前不可领取或续接。原详情页的刷新互斥及写后重读约束保持原行为；独立页的权限提示只控制按钮，实际请求仍重新授权。

加载/初次导入不改写浏览器存储，尚未保存的导入内容只在本页内存，重载后需重新导入。明确查询或重试沿用既有保存/读回逻辑，用户也可使用表单内的原请求恢复操作保存同一文本。保存槽冲突、损坏或存储不可用时禁用写入且不覆盖原值；保留内存原请求导出和显式回执查询。重试必须重新勾选确认，并在发送前保存及读回原请求，仍用原身份/版本/键。恢复及导入不自动查回执、不自动写业务、不分配新键。

无领取或写会话提示时仍可加载/导出原请求及显式请求原回执，服务端独立决定访问。未查到、旧记录未验证、认证/权限错误或详情不可读均保留未知。领取成功只确认原领取结果；续接成功只确认原子会话历史，不证明当前归属、上下文或子会话生命周期，当前状态仍通过独立链接读取。
