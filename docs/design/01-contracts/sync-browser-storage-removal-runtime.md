# 浏览器同步保存副本移除（开发契约）

2026-11-03：仅源码和文档，未编译、类型检查、测试、启动浏览器/服务、执行浏览器操作、访问 IndexedDB、生成样本或发布。沿用两份既有 IndexedDB v1 结构，无新增 shared wire/API/schema/依赖/SQL 迁移；R-005 仍未完成。

## 从目录选择并审阅

工作台 `/sync/receipt` 的原查询和历史回执目录各增加 `Remove browser copy…`。第一次点击只调用原有完整读取函数：原查询核验规范正文、原身份/事件键及所选元数据；回执还在读事务结束后独立计算并比对文档 SHA-256。目录摘要本身不作为删除依据。缺失显示当前不存在，损坏或与所选目录不符则不建立移除审阅。

读取成功显示独立审阅面板，固定副本类型、五字段原身份、event_id/type、完整规范 JSON；历史回执同时显示原查询 trace、历史结果与摘要。面板提供完整 JSON 复制和原格式下载入口，准备下载不等于文件已落盘。原查询下载仍是 `{identity,event}`，回执仍是既有 v1 完整文件，可用原导入路径恢复。

进入审阅不会载入为新的查询对象，也不会将历史回执显示为新的远端观察。用户勾选本条移除意图后点击 `Remove this browser copy` 才开始删除；每次尝试都会清除该勾选，失败后不会自动重试。审阅期间暂时禁用导入、目录切换、其他载入/移除操作，防止选中内容混用；有同步 ref 锁覆盖重新渲染前的重复点击窗口。忙碌时禁用移除/关闭/下载，卸载时取消当前等待。

取消审阅不访问存储。移除成功、两槽已缺失或未知失败后，完整审阅副本都继续留在面板中供复制/下载，直到用户关闭或离开页面。成功只从已显示目录移除对应行，不自动重新读取或全量扫描。目录续页仍按原键位置读取；关闭审阅后可显式刷新首屏了解当前存储。

## 精确删除与事务

`removeBrowserSyncOriginal(selection, expectedRaw, signal)` 接受选中的原目录键/完整元数据及已审阅规范原文。先重核原文与元数据，再以 `create:false` 打开已有 `planemem-sync-originals`。在一个覆盖 `originals/directory` 的 readwrite 事务内重新读取两槽，完整核验当前原文和目录，要求当前原文与审阅原文逐字相同、规范化元数据完全一致，才同时删除两槽。相同元数据或相同字节长度不能代替完整正文比较。

`removeBrowserSyncReceipt(selection, expectedRaw, signal)` 同样绑定所选摘要/元数据和完整审阅文件。先完整结构解析，并在事务外独立校验审阅文件的文档 SHA；期限/取消检查之后才打开已有 `planemem-sync-receipts`。写事务内完整核验当前 receipts/directory 两槽，并逐字比较当前原文与已经核验摘要的审阅原文，再执行成对删除。摘要工作不留在活跃 IndexedDB 事务中异步等待；即使另一个标签页在摘要期间改动记录，写事务也会重读并拒绝异文。

公共 `removeBrowserPair` 只在调用方完成完整核验后调用，删除正文和目录，再在同一事务读回两槽都不存在。只有事务完成事件成功、期限有效且未取消时才返回 `removed`。不存在数据库或两槽同时已不存在返回 `not-present`，这只说明此次观察到缺失，不归因于此前哪次操作。

单边缺失、非法目录、非字符串、损坏正文、异文或异元数据失败，不使用目录单独删除，也不清理无法核验的坏行。不执行 clear、删除数据库、覆盖或迁移。另一个标签页若重新保存完全相同的原文与元数据，本操作可移除该相同副本；当前 v1 没有记录创建代际，不能区分字节相同的删除再创建。另一个标签页也可以在事务结束后重新保存，成功不是未来永远缺失的承诺。

## 缺库、取消与结果保留

共用 `inBrowserStores` 增加 `options.create`；默认显式保存仍可创建 v1，readonly 永不创建，移除明确传 `create:false`。缺失数据库的初始 upgrade 被中止，不为删除永久创建空库；未知版本或异常对象存储结构继续拒绝，无 schema 改动。

打开和事务分别沿用 10 秒单调期限与 AbortSignal；回执移除的摘要、打开与事务另受原 30 秒整笔操作预算约束。取消/超时阻止迟到摘要启动新事务；事务错误尝试 abort，确认失败时不宣称删除未发生。UI 保留完整审阅副本，提示结果无法确认并让用户关闭审阅后重新读取目录；不会自动重试或自动恢复该副本。

同步解析和 IndexedDB 单次操作不能硬实时抢占，结构化克隆之前无法限制被外部损坏的超大值。沿用原查询/回执/元数据大小边界。此增量未产生浏览器事务、并发标签页、取消、配额、无障碍或下载运行证据。

## 范围

每次只针对所选数据库的一份副本；删除原查询不联动删除回执，删除回执不联动删除原查询或同事件的其他历史回执。页面当前查询/导入流程和远端回执查询语义保持原样；此操作不请求网络、不删除服务器证据、不撤销投递、不改变冲突/确认状态，也不操作 SQLite/outbox。需要重新保存时，可使用已下载或复制的完整原格式经过既有显式导入/保存流程。

批量备份/清理、损坏存储恢复、浏览器容量管理、跨设备队列恢复、其他业务原请求的管理及运行证据仍待补；单条副本移除不代表完整同步恢复闭环完成。
