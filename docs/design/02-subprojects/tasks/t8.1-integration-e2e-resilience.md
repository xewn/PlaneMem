# T8.1 集成、E2E、故障与性能测试编排

## 目标

把所有服务和 ai-memory/Plane 组成可重复集成环境并执行全链路与故障测试。

## 负责人和依赖

- 负责人：发布测试组
- 前置任务：T0.6、T1.5、T2.4、T3.4、T4.4、T6.3
- 所属子方案：根据任务编号归入对应 P0-P8；子方案入口见 ../P*/README.md。

## 文件和边界

tests/integration/*、tests/e2e/*、tests/resilience/*、tests/performance/*

本任务只能修改上述责任范围。跨目录修改必须先更新协接文档和 ADR。

## 输入

前置任务的版本化输出、`docs/design/01-contracts` 契约、`packages/test-fixtures` 共享 Fixtures，以及本任务声明的运行配置和权限上下文。


## 输出和接口

test environment contract、seed/reset、report format

当前落地：`apps/integration-orchestrator` 的 `runIntegrationScenario` 生成带 scenario、trace、
每步 source_refs 和 fault handling 结果的 `IntegrationReport`；`runPlaneToMcpScenario` 已实际
执行 canonical Plane `ProjectCreated` 事件、PlaneProjection、重复事件去重、ContextPack 编译、
scope fence 和 MCP Resource 读取。该链路只通过 P1/P2/P4 的公开包边界协接，不读取其他模块私有
数据库；真实 Plane Webhook 可按相同事件契约替换入口。
会话连续性 fixture 通过 P3/P2 的公开包边界执行 session、ai-memory capture、checkpoint、handoff
claim 和 resume，验证 claim-once、memory page ref、trace/source_refs 以及父子 session 关系；
指定 WaveMate 0.24.1 的真实客户端入口由 `tools/run-wavemate-live-probe.mjs` 覆盖，探针只使用
用户提供的离线包，通过 WaveMate 主机 API 配置 Streamable HTTP MCP 并捕获 discover/initialize/
initialized 和后续工具/资源请求。

任务输出必须带版本、trace_id、source_refs、scope 和错误封套。事件输出必须遵守 `docs/design/01-contracts/canonical-events.md`。

## 数据设计

canonical fixtures、golden project、fault switches

持久化数据必须有 migration、索引、租户/项目 scope、软删除或版本策略；不得直接写其他任务的数据库表。

## 实现步骤

1. 读取并确认前置任务的契约和 Fixtures；
2. 先为正常路径、权限拒绝、重复、超时和版本冲突编写失败测试；
3. 实现最小接口和运行时校验；
4. 接入 trace、audit、idempotency 和 health/readiness；
5. 在独立环境运行本任务测试；
6. 更新 OpenAPI/AsyncAPI/JSON Schema、Fixture、追踪矩阵和运行文档；
7. 生成可供下游消费的版本化 artifact。

## 独立测试

Plane→Webhook→Event→ContextPack→MCP、WaveMate MCP handshake、会话连续性 fixture、duplicate/out-of-order、NATS/DB restart、offline、security/perf

测试必须不依赖未完成的下游任务；需要外部能力时使用 packages/test-fixtures 或明确版本的 Compose 服务。

自动化入口：`P8-E01/T8.1`、`P8-E02/T8.1`、`P8-E05/T8.1`、`P8-E03/T8.1`；进程内公开边界链路由
`tests/p8/t8-release-deploy.test.ts` 和 `pnpm run test:e2e -- --chain <chain>` 执行，
真实 Plane/Webhook/MCP、WaveMate 0.24.1 和重启/断网属于 Docker/Nightly 门禁；本地 Compose 的
Workctx 进程 kill 和 ai-memory 网络分区/重连已实际执行，证据分别归档在
`artifacts/command-reports/p8-process-kill-current/` 与 `artifacts/command-reports/p8-network-partition-current4/`。`P8-E05/T8.1` 由
`tests/p8/t8-wavemate-live.test.mjs` 和 `pnpm run test:wavemate-live -- --live` 执行；`P8-E03/T8.1` 由
`tests/p8/t8-live-gates.test.mjs`、`tools/run-resilience-tests.mjs`、`tools/run-security-tests.mjs`
和 `tools/run-performance-tests.mjs` 覆盖；当前 Compose runtime 已完成 RabbitMQ 停止/恢复、scope
policy deny 和 100 请求并发 p95 探针，RC 级 NATS/PostgreSQL、Keycloak/OPA 业务恢复、生产负载仍保留外部门禁。
Compose 依赖业务恢复命令还在 PostgreSQL、NATS、RabbitMQ、ai-memory 各自 stop/start 后重新执行 12 步
Plane→MCP 平台探针，证据为 `artifacts/command-reports/p8-business-recovery-current2/`。

## 验收标准

所有阶段验收链路绿，失败能定位到 R/Task/trace

额外要求：失败必须返回可诊断的 trace_id；重试不得造成重复副作用；拒绝请求不得改变任何权威数据。

## 与其他任务的协接

### 消费

- 消费者只能调用本任务在 01-contracts 或本文件 输出和接口 中声明的 API/事件；
- 通过生成 SDK 或 HTTP/MCP Contract，不引用内部类、SQL 表或文件；
- 依赖版本写入 `release-manifest.yaml`，不使用浮动版本。

### 生产

- 生产的每个事件、API、Schema、迁移和配置都必须登记在 PR；
- 下游必须能通过 Fixture、Mock 或健康端点验证输出；
- 变更需在 docs/traceability/requirements-matrix.yaml 绑定需求和测试。

### 集成顺序

本任务先在自己的分支完成独立测试，再合并到 develop；集成测试通过后才允许被
release/* 引用。接口不兼容时禁止直接合并，必须走版本化迁移。

## 发布与回滚

本任务的镜像/包/迁移/配置必须能被 P8 收集到 Release Manifest。回滚时优先关闭 Feature Flag、回退应用版本并重放未确认事件；任何数据迁移回滚必须有验证脚本。
