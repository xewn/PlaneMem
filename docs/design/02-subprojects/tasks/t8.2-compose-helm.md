# T8.2 Compose、Helm 与部署拓扑

## 目标

交付开发/POC Compose 和生产 Helm/k3s 配置。测试部署只使用现有三节点 k3s 集群，不创建独立 Kubernetes 集群。

## 负责人和依赖

- 负责人：发布测试组
- 前置任务：T0.6、T4.1、T6.1、T6.3
- 所属子方案：根据任务编号归入对应 P0-P8；子方案入口见 ../P*/README.md。

## 文件和边界

deploy/compose/*、deploy/helm/*、deploy/config/*

本任务只能修改上述责任范围。跨目录修改必须先更新协接文档和 ADR。

## 输入

前置任务的版本化输出、`docs/design/01-contracts` 契约、`packages/test-fixtures` 共享 Fixtures，以及本任务声明的运行配置和权限上下文。


## 输出和接口

values.schema.json、health/readiness、secret refs、resource limits

当前落地：Compose 增加 `workctx` profile、固定依赖健康条件、数据库/NATS/Keycloak/MinIO/
ai-memory/OTel 地址和 proposal/vector 默认关闭；Helm Chart 提供 digest image、existingSecret、
资源限制、readiness/liveness 和 `values.schema.json`。`release-manifest-cli.mjs` 生成无占位符的
版本清单，`sbom-cli.mjs` 生成 CycloneDX 组件清单。

离线交付流程见[本地离线镜像构建与三节点传输设计](../../05-release/05-offline-image-build-transfer.md)。正式
WorkMesh 镜像现在由 `deploy/images/platform/Dockerfile` 提供可启动的 HTTP runtime，基础镜像由
digest 固定，`tools/stage-runtime.mjs` 生成自包含 workspace runtime。正式镜像构建、传输、
containerd 导入、Helm upgrade、rollback/restore、Pod 删除和 cordon 恢复证据见
[`20261021T0955-formal`](../../../../artifacts/test-reports/k3s/20261021T0955-formal/)。

任务输出必须带版本、trace_id、source_refs、scope 和错误封套。事件输出必须遵守 `docs/design/01-contracts/canonical-events.md`。

## 数据设计

config、secrets、feature flags、persistence claims

持久化数据必须有 migration、索引、租户/项目 scope、软删除或版本策略；不得直接写其他任务的数据库表。

## 实现步骤

1. 读取并确认前置任务的契约和 Fixtures；
2. 先为正常路径、权限拒绝、重复、超时和版本冲突编写失败测试；
3. 实现最小接口和运行时校验；
4. 接入 trace、audit、idempotency 和 health/readiness；
5. 在独立环境运行本任务测试；
6. 更新 OpenAPI/AsyncAPI/JSON Schema、Fixture、追踪矩阵和运行文档；
7. 生成可供下游消费的版本化 artifact。

## 独立测试

clean Compose、Helm lint/template/install/upgrade、restart、scale、secret missing

测试必须不依赖未完成的下游任务；需要外部能力时使用 packages/test-fixtures 或明确版本的 Compose 服务。

自动化入口：`P8-C01/T8.2`、`P8-C02/T8.2` 和 release contract；本地 Docker Compose 使用基础文件叠加
`docker-compose.local-test.yml` 并保存完整报告。Helm lint/template/install/upgrade 必须在具备对应 CLI
的 k3s 环境运行并保存报告。

当前已完成：本地 Docker Desktop 离线构建、正式 runtime 本机启动、k3s 三节点正式镜像部署、
健康/就绪/版本及 context index/search API 验证；本地集成 Compose 已使用固定 digest 启动
PostgreSQL、Redis、NATS、RabbitMQ、Keycloak、MinIO、OTel Collector、ai-memory、Plane 和
Workctx，完成数据库迁移、Plane 根路径、ai-memory Web、对象存储 bucket、Workctx index/search、
幂等重放及 RabbitMQ 故障恢复验证。运行入口是基础文件叠加
`deploy/compose/docker-compose.local-test.yml`，不能把该本地兼容覆盖文件当作生产配置来源。
完整证据见 [`20261021T1440-compose-full-plane`](../../../../artifacts/test-reports/compose/20261021T1440-compose-full-plane/)。

真实 Plane→Webhook→MCP、跨客户端 handoff、备份恢复、生产身份、负载和生产
Smoke 仍属于 RC 外部门禁；脚本在缺少这些外部条件时必须返回 `blocked`，不能用本地 Compose
健康结果替代这些门禁。

## 验收标准

干净环境可安装，错误配置在启动前失败

额外要求：失败必须返回可诊断的 trace_id；重试不得造成重复副作用；拒绝请求不得改变任何权威数据。

## 与其他任务的协接

### 消费

- 消费者只能调用本任务在 01-contracts 或本文件 输出和接口 中声明的 API/事件；
- 通过生成 SDK 或 HTTP/MCP Contract，不引用内部类、SQL 表或文件；
- 依赖版本写入 `release-manifest.yaml`，不使用浮动版本。

### 生产

- 生产的每个事件、API、Schema、迁移和配置都必须登记在 PR；
- 下游必须能通过 Fixture、Mock 或健康端点验证输出；
- 变更需在 docs/traceability/requirements-matrix.yaml 绑定需求和测试。

### 集成顺序

本任务先在自己的分支完成独立测试，再合并到 develop；集成测试通过后才允许被
release/* 引用。接口不兼容时禁止直接合并，必须走版本化迁移。

## 发布与回滚

本任务的镜像/包/迁移/配置必须能被 P8 收集到 Release Manifest。回滚时优先关闭 Feature Flag、回退应用版本并重放未确认事件；任何数据迁移回滚必须有验证脚本。
